What it's for

Three things NeoSCAD is built to do

Your models, unchanged

Open your existing .scad files. NeoSCAD reads OpenSCAD's language and uses OpenSCAD's own regression tests as its specification. MCAD and OpenSCAD's default Liberation fonts are built in, and BOSL2 works from your library path, as it does in OpenSCAD.

Live editing

neoscad serve keeps a model warm and re-renders only what an edit changed: about 0.25 s for an edit to the carrier of the gearbox above. The macOS app is built on the same engine, and neoscad lsp brings diagnostics and completion to any editor that speaks the Language Server Protocol.

Built for agents

An MCP server (neoscad mcp), JSON output from every command, and tools an agent can look through: snapshot renders a dimensioned four-view sheet, measure and check report sizes and printability. Resource limits stop a runaway model with an error instead of filling the machine.

Before you print

Check a model for printing

neoscad check renders the model and reports what would go wrong on an FDM printer, each finding with where it is and how to fix it:

  • a solid that isn't manifold, or breaks when written at STL's 32-bit precision;
  • pieces floating above the bed, and surfaces that would print fused;
  • walls thinner than the nozzle or your minimum wall;
  • overhangs steeper than your limit;
  • parts that intersect, and a model that doesn't fit your bed.
neoscad check part.scad \
  --nozzle 0.4 --min-wall 1.2 \
  --bed 256x256x256
neoscad snapshot part.scad --issues

snapshot --issues paints the findings onto the sheet: thin walls red, overhangs amber, floating pieces purple, with a numbered marker at each one. Add --format json for machine-readable output.

Built in the open

How NeoSCAD was made, and how it's checked

NeoSCAD was written by AI coding agents. Almost all of its code was written by Anthropic's Claude, working as coding agents under the direction of one person, who set the plan, reviewed each change and committed it. The first commit is from 25 September 2026, and the full history is public, with each change and the tests it had to pass. Built by Matt Robinson with Claude, supported by The Ned Workshop.

You shouldn't have to trust it because of who, or what, wrote it, so its behaviour is checked against OpenSCAD's:

  • OpenSCAD's regression suite is the specification. 1,773 in-scope tests pass, and a change may not make a passing test fail.
  • BOSL2: all 3,569 example and test files give the same echo output as the OpenSCAD nightly, and BOSL2's own 976 tests pass.
  • Differential tests compare NeoSCAD's parse tree, echo and CSG output with the nightly's, and every benchmark model's mesh with the nightly's (volume, area and bounding box).
  • Fuzzing: the polygon tessellator was fuzzed against OpenSCAD's C libtess2, and an evaluator prototype against the tree-walking evaluator.

The source is at github.com/neoscad/neoscad, under GPL-2.0-or-later, OpenSCAD's licence.

Coming from OpenSCAD

What's the same, and what isn't

The language, the libraries and the command line (neoscad model.scad -o model.stl) work as you know them. The differences today:

  • Geometry uses Manifold only; there is no CGAL backend.
  • text() uses the bundled Liberation fonts; system fonts aren't found yet.
  • The macOS app has no Animate panel, and the customizer is partial.
  • It is slower than the nightly on some models: deep unions, the Menger sponge at level 4, and models with many text() nodes.
  • Only macOS on Apple silicon for now.

Questions

Why not CadQuery or build123d?

They're good tools. They are Python libraries on a B-rep kernel, so they give you fillets on real edges and STEP output, which NeoSCAD, a mesh modeller like OpenSCAD, does not. NeoSCAD is for people and agents who already have OpenSCAD models and libraries such as BOSL2, or who want OpenSCAD's small declarative language and a fast edit-and-see loop.

Is it a drop-in replacement for OpenSCAD?

Not a claim we make. OpenSCAD's suite registers 3,258 tests. In the latest run 1,773 pass and 1,485 are skipped as out of scope: duplicates that only run on the CGAL backend (NeoSCAD uses Manifold only), experimental features, and tests that OpenSCAD itself marks as known bugs or disabled. The GUI is less complete than the command line.

Is it faster on every model?

No. On the 14-model benchmark it is about 2.8× faster than the nightly with Manifold on the heavy models, and 3.7× as a geometric mean including startup. It is slower on some deep unions, on the Menger sponge at level 4 and on models with many text() nodes. The benchmarks page has every number.

Which platforms does it run on?

The first release will be for macOS 15 or later on Apple silicon; it isn't out yet. Linux and Windows command-line builds (x86_64 and ARM) are planned, and an in-browser version is in progress. See downloads.

Who wrote it?

AI coding agents, directed by one person. How it was made and how it's checked covers it.
